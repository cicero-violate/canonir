Codex Command Protocol (Human-Readable)

This is how I typically communicate and execute work in this repo. It is not a network protocol; it is a task execution pattern.

1) Clarify scope
- Restate the request in plain language.
- Ask for missing details only if needed to proceed.

2) Inspect before editing
- Read relevant files first (e.g. rg, sed, cat) to confirm current behavior.
- Prefer minimal context loading; only open what is needed.

3) Propose a concrete plan (when non-trivial)
- Brief step list.
- Call out risks or tradeoffs.

4) Make changes
- Use precise edits (apply_patch for single-file edits; otherwise scripted edits).
- Keep changes localized and reversible.
- Avoid touching unrelated files.

5) Verify
- Run the requested checks (e.g. cargo check/build/test).
- Report failures with the key error lines and the likely fix.

6) Summarize
- State what changed.
- Note commands run.
- Point to modified files.
- Offer next steps if there are natural follow-ups.

Typical command shapes I run
- Search: rg -n "pattern" path
- View: sed -n 'start,endp' file
- Edit: apply_patch (small diffs) or cat <<'EOF' > file (new files)
- Build/test: cargo check / cargo build / cargo test (as requested)

Example execution transcript (format, not a real run)
- Inspect: rg -n "frames" canon-agent/src/ws_server.rs
- View: sed -n '420,520p' canon-agent/src/ws_server.rs
- Edit: apply_patch (replace .txt frame dumps with JSONL)
- Verify: cargo check

Notes
- I do not run destructive commands unless explicitly asked.
- I avoid changing files outside the target scope.
