## Architecture (stable — do not change)

```
canon-check (pure library)
  deps: serde_json only — zero coupling to event or capability system
  Check trait operates on &serde_json::Value
  CheckResult with defined semantics
  run_checks() / default_checks()

canon-runtime/consumers/check_consumer.rs
  filters to CanonEvent::Debug only (the only variant with an envelope)
  self-filter: d.source == "canon_check" → return
  builds minimal JSON: { "source", "kind", "payload" }
  calls run_checks()
  emits failures via canon_emit_meta!
```

**Why Debug-only filtering is correct:** Only `CanonEvent::Debug` events carry an envelope
(`payload.meta` + `payload.data`). Typed events (`CanonEvent::Cargo`, `File`, etc.) have no
envelope to validate — running envelope checks on them would produce spurious warnings.
The `EnvelopeCheck` already skips events without a `payload` field, but filtering at the
consumer level is cleaner and avoids unnecessary serialization.

**Why separation is non-negotiable:**
```
Before: canon-check → serde_json only
         coupling to event enum = 0

If execution added here: canon-check → canon-capability → canon-runtime-events
         coupling jumps to 1
         check layer becomes a miniature re-implementation of the executor
```

Execution testing already exists in `canon-introspection::assert_all_routes_safe`. It runs at
test time using `CanonEvent::sample_all()` (macro-generated, zero-maintenance). Do not duplicate it
in `canon-check`.

## What `canon-introspection` already provides

```rust
// canon-capability/src/tests.rs
fn all_capability_routes_are_safe() {
    let mut registry = CapabilityRegistry::new();
    register_editor_capabilities(&mut registry);
    canon_introspection::assert_all_routes_safe(&registry);
}
```

`assert_all_routes_safe` iterates `CanonEvent::sample_all()` — which is auto-generated by the
`canon_event_enum!` macro and always covers every variant. This is the execution guarantee.

The check layer is the stream-time structural guarantee. They are complementary, not overlapping.

## V Gap Analysis

`default_checks()` currently returns one check: `EnvelopeCheck`.

| Check | What it catches | Ships | Zero-maintenance |
|-------|----------------|-------|-----------------|
| EnvelopeCheck | `payload` key present + `meta` object + `data` key | ✅ | ✅ |
| SourceCheck | `source` field is present and non-empty | ❌ | ✅ |
| KindCheck | `kind` field is present and non-empty | ❌ | ✅ |
| MetaFieldsCheck | `meta.file`, `meta.line`, `meta.crate_name` non-empty/non-zero | ❌ (opt-in) | ✅ |

Adding `SourceCheck` and `KindCheck` to `default_checks()` raises V from 0.3 to ~0.7.
Adding `MetaFieldsCheck` (opt-in, not in `default_checks`) to cover semantic invariants raises
potential V to ~0.9. Users who call `run_checks` directly can opt into it.

## CheckResult Semantics (unchanged)

```rust
pub enum CheckResult {
    Ok,
    Warn(Vec<CheckWarning>),   // degraded but recoverable — emit, continue
    Err(Vec<CheckError>),      // invariant violation — emit, future escalation point
}
```

- `Warn`: structural expectation not met. System continues. Flags drift.
- `Err`: hard invariant broken. Reserved for future enforcement.

### SourceCheck

```rust
pub struct SourceCheck;

impl Check for SourceCheck {
    fn name(&self) -> &'static str {
        "source"
    }

    fn run(&self, event: &Value) -> CheckResult {
        let source = event.get("source").and_then(|v| v.as_str());
        match source {
            Some(s) if !s.is_empty() => CheckResult::Ok,
            Some(_) => CheckResult::Warn(vec![CheckWarning {
                check: self.name(),
                message: "source field is empty".into(),
            }]),
            None => CheckResult::Warn(vec![CheckWarning {
                check: self.name(),
                message: "source field missing".into(),
            }]),
        }
    }
}
```

### MetaFieldsCheck (opt-in only — do NOT add to `default_checks`)

```rust
pub struct MetaFieldsCheck;

impl Check for MetaFieldsCheck {
    fn name(&self) -> &'static str {
        "meta_fields"
    }

    fn run(&self, event: &Value) -> CheckResult {
        let Some(payload) = event.get("payload").and_then(|v| v.as_object()) else {
            return CheckResult::Ok;
        };
        let Some(meta) = payload.get("meta").and_then(|v| v.as_object()) else {
            return CheckResult::Ok; // EnvelopeCheck catches missing meta
        };

        let mut warnings = Vec::new();

        if meta.get("file").and_then(|v| v.as_str()).map_or(true, |s| s.is_empty()) {
            warnings.push(CheckWarning { check: self.name(), message: "meta.file is missing or empty".into() });
        }
        if meta.get("crate_name").and_then(|v| v.as_str()).map_or(true, |s| s.is_empty()) {
            warnings.push(CheckWarning { check: self.name(), message: "meta.crate_name is missing or empty".into() });
        }
        if meta.get("module").and_then(|v| v.as_str()).map_or(true, |s| s.is_empty()) {
            warnings.push(CheckWarning { check: self.name(), message: "meta.module is missing or empty".into() });
        }
        if meta.get("line").and_then(|v| v.as_u64()).map_or(true, |n| n == 0) {
            warnings.push(CheckWarning { check: self.name(), message: "meta.line is missing or zero".into() });
        }

        if warnings.is_empty() { CheckResult::Ok } else { CheckResult::Warn(warnings) }
    }
}
```

## Rejected Proposals (from external advice)

### `ExecutionCheck` in `canon-check`

Rejected. Reasons:
1. `canon-check` has `serde_json` only. Adding `ExecutionCheck` requires `canon-capability` dep.
2. Execution testing is already in `canon-introspection::assert_all_routes_safe`.
3. Running `registry.route(ctx)` inside `on_event` means every live event is executed twice —
   once by `CheckConsumer`, once by `CapabilityExecutor`. This is double-execution, not validation.
4. `ExecutionCheck::run` does `serde_json::from_value(event.clone())` to get `CanonEvent`. But
   `CanonEvent` only derives `Debug, Clone` — no `Deserialize`. This fails to compile.

### `CanonEvent::variants()`

Rejected. `sample_all()` already exists, generated by `canon_event_enum!` macro, covering all
variants automatically. The advice's `variants()` lists only 6 of 30+ variants — NOT
zero-maintenance. Any non-capability variant added is silently excluded.

### Score claims `R = 0, Z = 0.5`

Incorrect. `registry.route()` dispatches by type using `matches!` — R > 0. `EnvelopeCheck`
checks only key presence, no field names — Z = 1.0 for the check layer.
